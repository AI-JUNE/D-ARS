# D-ARS 발급 토큰 보안 요건 (TOKEN SECURITY)

> 명세의 단일 출처는 `lib/tokenAudit.js` 의 `TOKEN_SPECS` 다. `tests/tokenaudit.test.mjs` 가
> 이 문서 표와 양방향 대조하고, 선언된 수명이 **실제 구현 상수**(`EUM_TOKEN_TTL_MS`·`SESSION_HOURS`·
> `DEFAULT_TTL_SEC`)와 같은지도 확인한다.
> 점검: `npm run token:check [-- --profile=production]` — **비밀값은 물론 그 길이도 출력하지 않는다.**

## 1. 발급 토큰

세 토큰 모두 **무상태 HMAC-SHA256 베어러**다. 서버에 세션 저장소가 없으므로 서명 비밀이 곧
유일한 방어선이며, 비밀이 새면 임의의 토큰을 만들 수 있다.

| 토큰 | 용도 | 수명 | 전달 | 1회용 | 서명 비밀(폴백) |
| --- | --- | --- | --- | --- | --- |
| `auth-session` | 운영자 로그인 세션 | 8시간 | httpOnly 쿠키 | 재사용(설계상 정상) | `AUTH_SECRET` → 데모 기본값 |
| `rbac-session` | RBAC 미들웨어 세션 | 8시간 | httpOnly 쿠키 | 재사용(설계상 정상) | `RBAC_SESSION_SECRET`(폴백 없음 → 미설정이면 무동작) |
| `eum-link` | 이음 어르신 신청 링크 | 5분 | URL 경로 세그먼트 | **요건이나 미구현** | `EUM_TOKEN_SECRET` → `AUTH_SECRET` → 데모 기본값 |

## 2. 만료

- 세 토큰 모두 서명 페이로드 안에 `exp` 를 담고 검증 시 확인한다. 만료 없는 토큰은 없다.
- 로그인 쿠키의 `maxAge` 는 토큰 `exp` 와 **같은 상수**(`SESSION_HOURS`)에서 나온다.
  둘이 어긋나면 쿠키는 살아 있는데 토큰이 죽어 "로그인된 것처럼 보이는데 계속 401" 이 된다(테스트가 고정).
- `eum-link` 5분은 이음 가이드 §6-2 요건이다. 상한(10분)을 넘기면 판정이 경고/차단한다.

## 3. 1회용 — 미구현 (정직하게)

`eum-link` 는 요건상 1회용이지만, **실제로는 5분 안에 몇 번이든 재사용할 수 있는 베어러 토큰이다.**
링크를 받은 사람이 전달하거나 화면을 캡처해 공유하면 그 시간 동안 같은 신청 화면이 열린다.

진짜 1회용이 되려면 **사용 이력 저장소**가 필요하다(토큰마다 고유 id 를 부여하고, 첫 사용 시
기록한 뒤 재사용을 거부). 현재 구조는 무상태·무DB 전제라 그 저장소가 없다.

- 완화책(현재): 수명을 5분으로 짧게 잡고, 토큰에 개인정보를 담지 않는다(`sid`·`iat`·`exp` 뿐).
- 실구현은 DB 테이블 추가와 발급/검증 경로 변경을 수반한다 — **[승인 필요]**.
- 이 상태는 `token:check` 가 `TOKEN_NOT_ONE_TIME` 경고로 **매번 드러낸다**. 조용히 넘어가지 않는다.

## 4. 엔트로피(서명 비밀 강도)

| 등급 | 뜻 | 판정 |
| --- | --- | --- |
| `ok` | 32자 이상·반복 패턴 아님 | 통과 |
| `weak` | 짧거나 서로 다른 문자가 8종 미만 | 운영에서 차단, 그 외 경고 |
| `demo` | 저장소에 공개된 기본값 — **누구나 위조 가능** | 운영에서 차단, 그 외 경고 |
| `missing` | 미설정(폴백도 없음) | 경고(해당 기능이 동작하지 않는다) |

- 기준값 32자·8종은 관례에 따른 **운영 기준선**이며 실측 지표가 아니다.
- `eum-link` 가 전용 키 없이 `AUTH_SECRET` 을 빌려 쓰면 `TOKEN_SECRET_DERIVED` 경고가 난다 —
  한쪽이 유출되면 세션 위조와 링크 위조가 동시에 가능해지기 때문이다.
- 판정은 등급만 다룬다. **비밀값·길이·일부 문자를 반환하거나 출력하지 않는다**(테스트가 감시).

## 5. 전달 경로

- 쿠키 토큰: `httpOnly`(스크립트 접근 불가) · `sameSite=lax` · 운영에서 `secure` · `path=/`.
- `eum-link` 는 URL 에 실린다 → 접근로그·리퍼러·메신저 링크 미리보기로 새어나갈 수 있다.
  짧은 TTL 로 완화하지만 위험이 사라지는 것은 아니다(`TOKEN_IN_URL` 경고로 상시 표시).
- 토큰 페이로드에 개인정보를 담지 않는다. `eum-link` 는 `sid`(불투명 식별자)만 싣고 화면에도 표시하지 않는다.

## 6. 남은 일

- **[승인 필요] 운영 비밀값 주입** — `AUTH_SECRET`·`RBAC_SESSION_SECRET`·`EUM_TOKEN_SECRET` 각각
  **다른** 랜덤값. 자동화가 값을 만들지도 넣지도 않는다(`docs/STAGING_OPERATIONS.md` 2장).
- **[승인 필요] 1회용 저장소 도입** — 3장 참조. 도입 시 `TOKEN_SPECS.eum-link.oneTimeImplemented` 를
  켜고 이 문서 3장을 함께 고친다(테스트가 강제한다).
- **회전(rotation) 절차 미정** — 비밀값을 바꾸면 기존 세션이 전부 끊긴다. 무중단 회전은 서명 키를
  두 개 허용하는 구조가 필요하며 아직 없다.
- **판정은 정적이다** — 실제로 발급된 토큰을 검사하지 않는다. 명세·환경 구성만 본다.
