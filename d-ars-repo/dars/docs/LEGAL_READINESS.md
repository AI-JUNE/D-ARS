# 법적 고지 확정 절차 (LEGAL READINESS)

대상: 이용약관 · 개인정보처리방침. 정본 데이터는 `lib/legalContent.js` 하나이며 화면
(`/legal/terms`·`/legal/privacy`)은 그 데이터를 그대로 렌더한다(문안을 따로 품지 않는다 — 테스트가 감시).

## 이 문서가 있는 이유

문안 확정과 법무 검토는 **사람의 일**이고 자동화가 대신할 수 없다. 자동화가 할 수 있는 일은 하나다 —
**"아직 초안이다"가 조용히 사라지지 않게** 하는 것. 지금 구조에서 `LEGAL_META.status` 를 `'published'` 로
한 글자만 바꾸면 화면의 초안 배너가 사라지고, 사업자등록번호도 수탁자 목록도 보유기간도 비어 있는 문서가
그대로 정식 고지가 된다. 오류는 나지 않는다.

그래서 확정 조건을 체크리스트가 아니라 **판정**(`lib/legalReadiness.js`)으로 두었다. 체크리스트는 썩지만
판정은 썩지 않는다.

```
npm run legal:check     # 읽기 전용 · 네트워크·DB 무접속 · 환경변수 값 미출력
```

- 초안(`draft`) 단계에서는 **통과**한다(종료코드 0) — 빈 칸은 아직 사람의 차례다. 다만 무엇이 남았는지 매번 출력한다.
- 게시본(`published`)으로 바꾸는 순간 빈 칸·미확정 표식이 하나라도 있으면 **실패**한다(종료코드 1). CI 단계로 배선돼 있다.

## 사람이 채워야 할 칸

`lib/legalContent.js` 의 `LEGAL_META` — 지금은 의도적으로 비어 있다. **자동화는 이 값을 지어내지 않는다.**

| 항목 | 출처 | 상태 |
|---|---|---|
| `businessNumber` | 사업자등록증 | 미확정 |
| `address` | 사업자등록증(사업장 주소) | 미확정 |
| `privacyOfficer` | 개인정보 보호책임자 성명·직책 | 미확정(현재 방침 8장은 "대표"로만 표기) |
| `retentionNotice` | 이용기관 위탁계약·관계 법령 | 미확정(방침 4장이 "지체 없이 파기" 일반론) |
| `SUBPROCESSORS` | 처리위탁 계약(수탁자·위탁업무 내용) | 비어 있음 |

`contactEmail` 은 현재 개인 메일 도메인이다. 공식 도메인 주소로 바꾸는 편이 낫지만 형식 검증은 통과하므로
차단 사유는 아니다.

### 수탁자 공개 목록에 관하여

개인정보 보호법 §26 은 수탁자와 위탁업무 내용을 방침에 공개하도록 한다. 저장소 구성상 후보는
**데이터베이스 호스팅과 애플리케이션 호스팅**이며(의존성·배포 설정에서 확인된다), 무엇을 어떤 문구로
공개할지는 계약·법무 확정 사항이라 코드가 임의로 채우지 않았다 **[승인 필요]**.

## 판정 코드

| 코드 | 뜻 |
|---|---|
| `META_MISSING` | 확정 필수 항목이 비어 있다 |
| `CONTACT_INVALID` / `EFFECTIVE_DATE_INVALID` | 형식 오류 — 초안 단계에서도 실패 |
| `STATUS_UNKNOWN` | `status` 가 `draft`/`published` 가 아니다(초안으로 간주) |
| `PENDING_MARKERS` | 게시본인데 본문에 `[승인 필요]`·⚠️·TBD 가 남아 있다 |
| `SUBPROCESSORS_EMPTY` | 수탁자 공개 목록이 비어 있다 |
| `CLAIM_AHEAD_OF_CODE` | 방침이 **아직 켜지지 않은 보호조치**를 시행 중이라고 서술한다 |
| `DRAFT_UNMARKED` | 초안인데 본문에 미확정 표식이 없다(읽는 사람이 확정본으로 오해) |
| `RETENTION_VAGUE` | 보유·이용기간 조항에 구체적 기간이 없다 |

### `CLAIM_AHEAD_OF_CODE` — 지금 걸려 있는 항목

방침 7장은 "접근권한 관리(RBAC)·접근 통제 … 를 시행합니다" 라고 단언하는데, 라이브는 `AUTH_ENFORCE` 가
꺼져 있어 인증이 강제되지 않는다(`docs/AUTH_ROLLOUT.md`). 초안 단계에서는 경고지만 **확정본에서 이 어긋남은
허위 서술**이므로 차단으로 승격된다. 해소 방법은 둘 중 하나다 — 실인증을 켜거나(**[승인 필요]**), 문안을
현재 시행 중인 조치만 서술하도록 고치거나.

## 게시 절차

1. 위 표의 칸을 `lib/legalContent.js` 에 채운다(사업자등록증·위탁계약 기준).
2. 본문의 `[승인 필요]`·⚠️ 문구를 확정 문안으로 교체한다.
3. `npm run legal:check` 가 차단 0건이 될 때까지 반복한다.
4. 법무 검토 완료 후에만 `LEGAL_META.status` 를 `'published'` 로 바꾸고 `effectiveDate` 를 갱신한다 **[승인 필요]**.
5. 개정 시에는 방침 9장·약관 3조의 사전 고지 기간(7일 / 중대 변경 30일)을 지킨다.

## 한계(정직하게)

- 이 게이트는 **문안의 법적 적정성을 판정하지 않는다.** 칸이 채워졌는지, 서술이 코드 상태와 어긋나지 않는지만 본다.
  법무 검토를 대체하지 않는다.
- `CLAIM_AHEAD_OF_CODE` 는 접근통제 서술 하나만 대조한다. 다른 서술(암호화·보관기간 등)과 구현의 대조는 미구현이다.
- 개정 이력(버전·개정일 누적)은 관리하지 않는다 — 현재는 시행일 한 줄뿐이다.
