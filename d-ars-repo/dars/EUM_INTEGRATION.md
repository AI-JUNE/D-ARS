# 이음 2R 연동 과제 — 어르신 선택 화면 (가이드 §6-2)

D-ARS 를 **「이음 어르신 신청」 화면 하나로 축소**한 별도 라우트를 만든다. 기존 D-ARS 제품은 그대로 두고, `/eum/senior/[token]` 경로만 추가한다.

## 요건
- 1회용 토큰 링크(5분 만료), 회원가입 없음
- 글자 18pt 이상, 버튼 한 화면 4개 이내, 명도 대비 4.5:1
- 화면 흐름: 희망 활동(4개 중 택) → 희망 시간대(4개 중 택) → 확인 → 완료
- 완료 시 `POST {EUM_API}/seniors/{id}/preferences` (토큰 검증) — 실연결 전엔 콘솔 로그 + 로컬 저장
- 페이지 제목 「이음 어르신 신청」. 로고·도입사례·요금표 **표시 금지**
- 음성(콜봇)과 화면 단계가 어긋나지 않도록 `step` 을 URL 상태로 유지

## 남은 승인 사항
- **[승인 필요] 이음 API 실연결** — 제출은 이제 자사 서버까지 도달하지만, 거기서 **이음으로는 보내지
  않는다**. 접수 기록은 구조화 로그 한 줄뿐이다(Vercel 함수 로그 보존기간에 종속).
  실연결 시 `app/api/eum/senior/preferences/route.js` 의 `[승인 필요]` 주석 자리에서
  `POST {EUM_API}/seniors/{sid}/preferences` 를 호출한다. 그때 **전송 실패 시 소진 기록을 되돌려
  재시도를 허용할지**를 함께 정해야 한다(지금은 접수=소진이라 되돌릴 자리가 없다).
- **[승인 필요] 발급 화면·API** — 지금 발급은 **CLI 뿐**이다(`npm run eum:link`). 담당자가 웹에서
  누르는 발급 버튼은 만들지 않았다: 이 링크는 그 자체가 인증 수단인데 라이브는 `AUTH_ENFORCE` 가
  꺼져 있어(docs/AUTH_ROLLOUT.md), 지금 발급 라우트를 열면 **누구나 임의 sid 로 링크를 찍어**
  담당자 명단에 신청을 밀어 넣을 수 있다. 판정을 켤 수 없는 상태에서 문을 먼저 내는 것은 순서가
  뒤바뀐 일이라, 발급 라우트는 실인증 전환과 **함께** 열어야 한다.
- **[승인 필요] `EUM_TOKEN_SECRET` 설정** — 미설정 시 `AUTH_SECRET`, 그것도 없으면 데모 기본값을
  쓴다. 실운영 링크 발급 전에 반드시 전용 비밀값을 넣어야 한다.

## 알려진 한계 (숨기지 않는다)
- 소진 기록은 **인메모리·인스턴스 로컬**이다(`lib/apiLimits` 와 같은 한계). 서버리스 인스턴스가
  여러 개면 다른 인스턴스로 간 재제출은 걸러지지 않는다 — 즉 1회용은 **실질적 보장이지 절대 보장이
  아니다**. 공유 저장소(DB·Redis) 영속화는 **[승인 필요]**이며, `createConsumeStore` 와 같은 모양의
  어댑터를 끼울 수 있게 인터페이스를 좁게 잡아 두었다.
  이 한계가 **실제로 발동한 순간**은 이제 관측된다 — 상한 축출은 라우트가 `eum_consume_evicted`
  경고로 남기고, 지금 상태는 `/api/health` 의 `eum-onetime` 이 말한다(`audit-persist` 와 같은
  한계: **그 인스턴스의** 신호이지 전체 총계가 아니다).
- 서버 재시작·재배포 시 소진 기록이 비워진다. 5분 만료가 피해 범위를 그만큼으로 한정한다.
- 진입 화면의 「이미 신청하셨습니다」는 링크가 **아직 살아 있을 때만** 나온다. 소진 기록은 토큰
  만료와 함께 사라지므로, 만료 뒤 다시 연 사람에게는 만료 안내만 보인다(접수 여부를 알 방법이
  없어 지어내지 않는다). 그 사람이 새 링크를 받아 다시 신청하면 명단에 두 건이 남는다 —
  공유 저장소 영속화 **[승인 필요]** 전에는 닫히지 않는 경로다.

- **만료 임박을 보이지 않는 사용자가 알 수 없던 것을 고쳤다.** "잠시 후 이 화면이 닫힙니다" 는 눈으로만
  보이는 문단이었다 — 스크린리더 사용자는 화면이 곧 닫힌다는 것을 끝내 듣지 못한 채 작성 중 만료를 맞았다.
  문단을 낭독 영역(`role="status" aria-live="polite"`)으로 두되 **매초 바뀌는 초 숫자는 `aria-hidden`** 으로
  뺐다. 넣어 두면 1초마다 낭독이 끊기고 처음부터 다시 읽혀 오히려 문장을 들을 수 없다. 문구
  `EUM_SOON_MESSAGE` 에 숫자를 넣지 못하게 테스트가 막는다.
- **제출 한도의 키를 링크 단위로 바꿨다.** `lib/apiLimits` 헤더는 "서명이 유효하면 그 단위로, 검증 실패만
  IP 단위로" 를 규칙으로 못박아 두고 CGNAT 무고한 차단을 피한다고 적고 있는데, **이 라우트만 그 규칙에서
  빠져** 처음부터 IP 로 조이고 있었다 — 하필 공유 IP 가 가장 흔한 경로에서. 복지관·경로당에서 담당자가
  여러 어르신을 한 자리에 모아 놓고 링크를 하나씩 보내는 것이 이 기능의 전형적인 사용 장면이고, 그 방은
  공유기 하나 뒤에 있어 공인 IP 가 하나다. 앞사람들의 재시도(손이 떨려 여러 번 누르는 것까지)가 한도를
  채우면 아무 잘못도 하지 않은 뒷사람이 「잠시 후 다시 눌러 주세요」만 보다가 5분 링크를 잃는다.
  정책표 주석은 "공유 IP 에서 잇따라 신청하는 상황도 막지 않아야 한다" 고 적어 두었지만 IP 키로는
  **코드가 보장할 수 없는 서술**이었다. 이제 유효한 링크는 `consumeKey`(서명 부분 · 소진 기록과 같은 키)로
  세고, 위조 토큰 홍수만 `tokenFail`(IP 단위)이 막는다. 한도 값은 그대로다.
- 한계: 위 세 건 모두 **소스 불변식·단위 테스트**로 고정했다. 실기기(시계가 틀린 단말·스크린리더)
  확인은 유효 토큰 링크가 필요해 이번에도 대신하지 못했다. `npx next build` 는 이 실행 환경에서 여전히
  시간 초과이며 실배포 빌드는 Vercel 이 판정한다.
